# Чайная история · подключение к 1С

## Что уже готово в веб-приложении

- Заказы и изменения складских остатков сохраняются в PostgreSQL.
- Каждое изменение попадает в outbox-очередь с уникальным ключом идемпотентности.
- Очередь переживает перезапуск сервера и повторяет временно неуспешную отправку.
- Администратор видит состояние очереди и может проверить доступ к 1С из рабочего кабинета.
- Секреты 1С не хранятся в браузере или базе приложения — только в защищённом окружении сервера.

## Что запросить у директора и специалиста 1С

1. Полное название конфигурации: например, 1С:Розница, 1С:УНФ или 1С:Управление торговлей.
2. Версию конфигурации и версию платформы 1С:Предприятие.
3. Где находится база: локальный сервер, облако 1С:Фреш или сервер подрядчика.
4. Отдельную копию или тестовую базу. На боевой базе разработку обмена не начинаем.
5. HTTPS-адрес тестовой публикации и IP/домен, с которого разрешены запросы.
6. Отдельного сервисного пользователя с минимальными правами. Не использовать логин директора или кассира.
7. Контакт 1С-разработчика, который может добавить расширение/HTTP-сервис и подтвердить структуру объектов.
8. Выгрузку или описание справочников: номенклатура, характеристики, единицы, склады, типы цен, контрагенты, дисконтные карты.
9. Какой документ должен создаваться из веб-заказа и на каком статусе: заказ покупателя, чек ККМ, реализация или иной документ.
10. Кто является источником истины по остаткам, ценам, гостям и бонусам.
11. Требуемую частоту обмена, часовой пояс, правила возврата и отмены.
12. Три тестовых сценария с ожидаемым результатом: заказ, отмена, изменение остатка.

## Предлагаемый контракт HTTP-сервиса 1С

`GET /hs/chay/health` возвращает HTTP 200.

`POST /hs/chay/exchange` принимает событие:

```json
{
  "event": "order.changed",
  "entity": { "type": "order", "id": "ord_..." },
  "payload": {},
  "occurredAt": "2026-08-22T12:00:00.000Z"
}
```

Заголовок `Idempotency-Key` обязателен: повтор запроса не должен создавать второй документ.

## Переменные production-сервера

```text
ONEC_BASE_URL=https://test-1c.example.ru/base
ONEC_USERNAME=chay_exchange
ONEC_PASSWORD=long-random-secret
ONEC_HEALTH_PATH=/hs/chay/health
ONEC_EXCHANGE_PATH=/hs/chay/exchange
```

## Порядок ввода

1. Утвердить карту данных и владельца каждого справочника.
2. Поднять HTTP-сервис в тестовой базе 1С.
3. Включить доступ только с production-сервера VetSvet/Chay по HTTPS.
4. Пройти заказ → изменение → отмена → повтор события без дубля.
5. Сверить суммы, НДС, единицы и остатки.
6. Сделать резервную копию и только затем включить боевой обмен.

Живой обмен нельзя честно назвать завершённым до получения тестового доступа и подписания карты данных специалистом 1С.
