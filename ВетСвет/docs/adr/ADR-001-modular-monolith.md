# ADR-001: модульный монолит в начале

**Статус:** принято

## Контекст

VetSvet содержит много взаимосвязанных транзакционных доменов: запись, платежи, документы, медицинская история, коммуникации и доступы. Разделить их в микросервисы до появления стабильных потоков означает получить дорогую распределённую сложность без выигрыша.

## Решение

Строим один развёртываемый backend с изолированными доменными модулями, application services, репозиториями, явно типизированными контрактами и transactional outbox. Внешние системы подключаются адаптерами. Границы модулей и события проектируются так, чтобы востребованный модуль можно было выделить позже.

## Последствия

- Простые согласованные транзакции и единый audit на старте.
- Нужна дисциплина зависимостей: нет импорта «всего отовсюду» и доступа UI напрямую к БД.
- Горизонтальное выделение сервисов — осознанное решение на основании нагрузки/ownership, не косметический рефакторинг.
