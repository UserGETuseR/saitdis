# VetSvet

VetSvet — цифровая система жизни питомца и работы современной ветеринарно-груминговой организации. Это отдельный продукт: его код, данные и развёртывание не смешиваются с текущим магазином в корне репозитория.

## Стартовая точка

В папке уже лежит исходный полный план: `VetSvet_Master_Vision_for_Codex_v2_FullScale.md`. Он остаётся первоисточником требований. Рабочие решения, архитектура и статус реализации ведутся в [`docs`](./docs).

## Запуск локально

На Windows дважды откройте [`RUN_VETSVET.cmd`](./RUN_VETSVET.cmd), либо запустите `RUN_VETSVET.ps1` из PowerShell. Откроются независимые локальные поверхности:

- `http://127.0.0.1:4300` — Public Web;
- `http://127.0.0.1:4300/client/` — кабинет владельца;
- `http://127.0.0.1:4300/staff/` — рабочее место команды;
- `http://127.0.0.1:4300/api/healthz` — статус development API.

Локальный сервер использует только in-memory адаптер для безопасной разработки. Production-запуск будет работать с PostgreSQL, приватным хранилищем и секретами окружения, а не с этой временной конфигурацией.

## Как будем строить

1. Сначала — безопасное ядро: организация, локации, идентичности, права, владелец, питомец, файлы, аудит и события.
2. Затем — единый UX-фундамент: дизайн-система, доступность, язык интерфейса и сценарии клиента/команды.
3. Потом — реальные end-to-end цепочки: запись и оплата → полный груминг-цикл → консультация → клинический приём.
4. Каждая функция выходит только с правами, журналом действий, состояниями загрузки/ошибок, аналитикой без персональных данных и проверкой критичного пути.

## Продуктовые принципы

- Красота не должна тормозить действие и повышать тревогу.
- Владелец всегда понимает: что происходит, сколько это стоит, кто отвечает и что делать дальше.
- Срочная помощь, медицинские данные и подтверждение оплаты важнее любых эффектов.
- Питомец — центр истории, а не вложенное поле в карточке клиента.
- Система помнит контекст, но не собирает лишнего и не использует тёмные паттерны.
